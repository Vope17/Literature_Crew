# Literature Crew 前後端架設說明

Literature Crew 是一個文獻搜尋與綜述工具：前端使用 **Vue 3 + Vite**，後端使用 **FastAPI + CrewAI**，Python 依賴以 **uv** 管理。本文件說明如何在本機架設開發環境與單一伺服器部署。

> 本應用程式沒有登入驗證機制，僅適合在本機（localhost）使用，請勿直接對外開放。

## Docker 執行方式（建議）

只需要 Docker Engine 與 Compose v2.24 以上，uv、Python、Node 與官方 AI CLI
均在容器中安裝，不需要在主機安裝開發依賴。

```sh
make env
# 編輯 backend/.env 選擇 AI_BACKEND
docker compose up --build -d
```

開啟 <http://localhost:8000>。查看日誌與執行測試：

對外入口為 Nginx：`localhost:8000 → nginx:80 → app:8000`，FastAPI 不直接
發布主機連接埠。設定在 `nginx/default.conf`，包含搜尋重試所需的 300 秒等待時間（包含 AI 關鍵字萃取）、
代理標頭及後端容器重建後的 DNS 更新。可用 `docker compose exec nginx nginx -t`
檢查設定。設定檔直接打包進 Nginx 映像，修改後執行 `docker compose up --build -d nginx`。

```sh
docker compose logs -f app
make docker-test
docker compose down
```

`literature-data` volume 儲存 Docker 版本的歷史紀錄與 PDF；主機原本的
`backend/data/` 不會自動匯入。`codex-login` 與 `claude-login` volumes 分別保存
官方 CLI 登入，請當作帳號憑證保護。一般 `docker compose down` 會保留它們，
不要加 `-v`，除非確定要刪除這些資料。

### 選擇 API 或訂閱登入

前端右上角的「⚙ 設定」集中提供外觀、AI 連線與模型選擇。
選擇「OpenAI API」後可輸入金鑰並按「驗證 API 連線」；訂閱登入或 API 驗證
成功後才會顯示模型下拉選單。前端輸入的金鑰暫存於後端記憶體，最長八小時，
並以 HttpOnly cookie 識別各瀏覽器連線。服務重啟後需重新輸入，歷史紀錄不儲存金鑰。
外觀可選淺色、深色與跟隨系統，選擇保存在瀏覽器。

在 `backend/.env` 設定下列其中一種方式：

| AI_BACKEND | 使用方式 | 模型設定 |
|---|---|---|
| `openai_api` | 現有 OpenAI API key，依 API 用量計費 | `MODEL=openai/...` |
| `codex_cli` | 官方 Codex CLI 登入自己的 ChatGPT 帳號 | `CLI_MODEL` 選填 |
| `claude_cli` | 官方 Claude Code 登入自己的 Claude 訂閱帳號 | `CLI_MODEL` 選填 |

ChatGPT 訂閱模式：

```dotenv
AI_BACKEND=codex_cli
CLI_MODEL=
CLI_TIMEOUT_SECONDS=600
```

在自己的終端機執行並完成官方登入：

也可以直接開啟前端設定面板，點 **Connect ChatGPT subscription**，複製一次性驗證碼，
再點 **Open OpenAI sign-in** 到官方頁面輸入驗證碼並授權。頁面會自動更新為已連線；
不需要額外發布 Docker 回呼連接埠。若官方要求，先在 ChatGPT 安全性設定或工作區
權限中啟用裝置驗證。尚未完成的登入可取消，逾時後可以重試。連線狀態不代表已驗證
所有模型權限；實際產生時仍受帳號額度與模型權限限制。

終端機登入方式仍可使用：

```sh
docker compose run --rm app codex login --device-auth
docker compose run --rm app codex login status
docker compose up -d
```

Claude 訂閱模式改成 `AI_BACKEND=claude_cli`，再執行：

```sh
docker compose run --rm app claude auth login
docker compose run --rm app claude auth status
docker compose up -d
```

如果容器無法自動開啟瀏覽器，將 CLI 顯示的網址貼到自己的瀏覽器，並依終端機
指示回填授權碼。登入由未修改的官方 CLI 處理；應用程式不讀取 token 檔案或
瀏覽器 cookie。容器登入與主機原有登入各自獨立。

CLI 模式不使用 `MODEL`、`OPENAI_API_KEY`，也不會在失敗時自動切換 API 計費。
`CLI_MODEL` 留空使用 CLI 預設模型，指定時使用該 CLI 的原生名稱，勿加 `openai/`。
介面的「CLI available」表示 CLI 已安裝；產生報告時才檢查登入。
帳號方案須具備對應 CLI 使用權限，額度、模型權限與額外用量依自己的帳號設定。
本整合限此本機個人使用情境，不提供共用訂閱帳號服務。

官方文件：[Codex 登入](https://learn.chatgpt.com/docs/auth)、
[Codex 非互動模式](https://learn.chatgpt.com/docs/non-interactive-mode)、
[Claude Code 程式化執行](https://code.claude.com/docs/en/headless)、
[Claude Code 登入](https://code.claude.com/docs/en/authentication)、
[Claude Code 憑證使用規範](https://code.claude.com/docs/en/legal-and-compliance)。

### 文獻與緒論報告

連線可用後，設定面板會載入模型下拉選單。OpenAI API 與 ChatGPT 訂閱分別讀取
各自的模型目錄，Claude Code 提供 Sonnet、Opus、Haiku 官方別名。
可點 Refresh models 更新選項，所選模型會用於這次報告，並隨歷史紀錄保存。
模型實際權限與額度會在產生報告時由供應商確認。

搜尋後可選文獻綜述或緒論草稿，並選擇繁體中文／英文。緒論模式可填暫定標題、
動機、研究問題、目標、情境、分析單位、預計方法及貢獻；空白資料會在草稿中標示待補。
輸出設定、AI 使用方式與檢查結果會隨歷史紀錄保存。

分析先產生具來源與頁碼的結構化證據，再按主題綜合共同發現、相反結果與候選缺口。
「Evidence checks」檢查來源編號、實際提供的頁碼與文字覆蓋程度；無法代替人工判讀
引用是否支持主張，也不能證明所選幾篇論文涵蓋整個領域。

以下為不使用 Docker 時的本機開發方式。

```
Literature_Crew/
├── backend/              # FastAPI + CrewAI 後端
│   ├── app.py            # API 路由入口
│   ├── literature.py     # PDF 擷取與 CrewAI 綜述流程
│   ├── paper_search.py   # arXiv 搜尋
│   ├── semantic_search.py# Semantic Scholar 搜尋
│   ├── openalex_search.py# OpenAlex 搜尋（期刊、研討會、預印本）
│   ├── search_catalog.py # 多來源並行查詢、合併去重
│   ├── paper_urls.py     # 公開網址檢查、DOI 正規化、PDF 安全下載
│   ├── review_jobs.py    # 背景綜述工作佇列
│   ├── storage.py        # SQLite 歷史紀錄與 PDF 儲存
│   ├── .env.example      # 環境變數範本
│   └── tests/            # 後端測試
├── frontend/             # Vue 3 + Vite + TypeScript 前端（pnpm test 含型別檢查）
│   └── src/              # App.vue、ReportView.vue、ReviewProgress.vue 等
└── docs/                 # 規格與說明文件
```

## 3. 後端架設

### 3.1 安裝依賴

```sh
cd backend
uv sync
```

`uv sync` 會依照 `uv.lock` 建立 `backend/.venv` 並安裝所有套件（第一次執行需要幾分鐘）。

### 3.2 設定環境變數

從範本建立 `.env`（已存在時不會覆蓋）：

```sh
cp -n .env.example .env
```

編輯 `backend/.env`：

```dotenv
OPENAI_API_KEY=你的-API-key
MODEL=openai/gpt-4o-mini

# SQLite 歷史紀錄與 PDF 儲存位置；相對路徑以 backend/ 為基準
HISTORY_DB_PATH=data/history.sqlite3

# 選填：各搜尋來源的 API key，可降低被限流的機率
SEMANTIC_SCHOLAR_API_KEY=
OPENALEX_API_KEY=

CREWAI_TRACING_ENABLED=false
OTEL_SDK_DISABLED=true
```

說明：

- **搜尋前須完成 AI 連線**：系統先使用選定的 AI 與模型萃取 1–4 組英文關鍵詞（合計最多十個詞），再查詢論文來源。可使用 API 或 CLI 訂閱。
- 輸入最多 10,000 字元，支援中英文研究描述；原文保留作為報告主題。結果與歷史紀錄會顯示實際萃取的關鍵詞。
- 設定中的 **Interface language／介面語言** 可切換英文與繁體中文，選擇會記在目前瀏覽器；報告輸出語言另外設定。
- AI 同時解析學科、年份及明確要求的結果數（1–10 篇）。例如「我想找 linux 網路相關的推薦一下，2025-2026 的」會推導出 `Linux`、`networking`、資訊科學與 2025–2026 年；實際條件會顯示在結果上並回填篩選欄位。
- 手動修改的篩選欄位優先於 AI，直到按「重設篩選」。重設會清除手動優先狀態、學科與年份，結果數恢復 5。未手動指定的欄位每次重新解析，不會沿用上次 AI 推測的條件。
- 此流程使用結構化輸出，由後端驗證參數後查詢 arXiv／Semantic Scholar，不需要讓模型自行執行 tool-use 迴圈；歷史紀錄保存實際生效的條件與結果數。
- 每次搜尋都會使用 AI 額度，即使論文來源命中快取；萃取失敗會顯示錯誤，不會直接拿原文查詢。
- 搜尋框不再直接傳遞 arXiv 進階語法。萃取後的關鍵詞仍由 arXiv 以 AND 比對，尚未實作 embedding 語意檢索。
- 本機 CLI 模式需要後端使用者已安裝並登入 `codex` 或 `claude`，且該 CLI 位於後端 `PATH`。
- 後端設定的 API key 不會回傳前端。前端輸入的金鑰會送至後端驗證，金鑰不會寫入歷史紀錄。
- `.env` 已列在 `.gitignore`，不會被提交到 Git。
- 修改 `.env` 後必須**重新啟動後端**才會生效；系統環境變數的優先權高於 `.env`。

### 3.3 啟動後端

在**專案根目錄**執行：

```sh
uv run --directory backend uvicorn app:app --reload
```

或已經在 `backend/` 目錄中時：

```sh
uv run uvicorn app:app --reload
```

`--reload` 會在程式碼變更時自動重啟，適合開發使用。啟動後可檢查：

- API 文件：<http://localhost:8000/docs>
- 設定狀態：<http://localhost:8000/api/config>（`ready` 表示設定可用；CLI 登入於產生時檢查）

注意事項：

- **只執行一個後端程序**，不要加 `--workers`；綜述工作佇列存在單一程序中，一次執行一個綜述，其餘排隊。
- SQLite 資料庫會在第一次啟動時自動建立於 `backend/data/history.sqlite3`，請定期備份此目錄以保留歷史與 PDF。
- 後端中斷時正在執行的綜述，會在下次啟動時標記為失敗，可從歷史紀錄重新產生。

## 4. 前端架設（開發模式）

另開一個終端機，在專案根目錄執行：

```sh
cd frontend
pnpm install
pnpm dev
```

開啟 <http://localhost:5173>。Vite 會將 `/api` 請求代理到後端的 `http://127.0.0.1:8000`，因此**後端必須同時在執行**。

---

## 5. 單一伺服器模式

不需要 Vite 開發伺服器時，可先建置前端，再由 FastAPI 一併提供網頁：

```sh
pnpm --dir frontend install
pnpm --dir frontend build
uv run --directory backend uvicorn app:app
```

開啟 <http://localhost:8000>。

- FastAPI 只在**啟動時**偵測 `frontend/dist` 是否存在；建置後需重新啟動後端。
- 前端有修改時，需重新執行 `pnpm --dir frontend build`。

測試使用本機 PDF 與模擬服務，不需要 API key，也不會消耗額度。

## 7. 常見問題

**`error: No such file or directory (os error 2)`**
通常是 `uv run --directory backend` 在 `backend/` 內執行，導致尋找不存在的 `backend/backend`。請改在專案根目錄執行，或在 `backend/` 內去掉 `--directory backend`。

**`Port 8000 / 5173 is already in use`**
已有後端或前端在執行。可沿用現有程序，或先停止它：

```sh
lsof -i :8000
```

**前端顯示「Cannot reach the server」**
後端沒有啟動，或不在 8000 埠。請先啟動後端再重新整理頁面。

**模型標籤顯示「setup needed」、無法產生綜述**
先查看介面的設定提示。API 模式需要 `OPENAI_API_KEY` 與 `MODEL`；CLI 模式需要
官方 CLI 已安裝並登入。Docker 中修改 `.env` 後執行 `docker compose up -d`。

**搜尋顯示限流倒數**
所選的搜尋來源（arXiv、Semantic Scholar、OpenAlex）全部暫時限制請求才會出現倒數；只有部分來源失敗時，會先顯示其他來源的結果。等待倒數結束再試；相同搜尋 15 分鐘內會使用快取。可設定 `SEMANTIC_SCHOLAR_API_KEY`、`OPENALEX_API_KEY` 降低限流機率。

**`pnpm` 或 `node` 出現 `_nvm_load` / `maximum nested function level reached`**
這是 shell 中 nvm 延遲載入設定的問題，在非互動式 shell（例如 IDE 或腳本）中發生。可改用 Node 的絕對路徑執行，或在互動式終端機中操作。

## 8. 使用限制

- PDF 下載上限 20 MB。逐頁擷取文字並渲染頁面影像（最長邊 2,000 像素；PNG 超過 4 MB 時再縮小），交由支援視覺與結構化輸出的模型分批分析；掃描頁也會送入影像辨識。
- `PDF_BATCH_PAGES=4`：每批預設 4 個頁面輸入，可設 1–8。每批文字最多 24,000 字元、PNG 合計最多 12 MB；單頁文字超過 12,000 字元時會分段處理，保留原始頁碼與全部文字。
- `PDF_MAX_PAGES=200`：每篇預設最多 200 頁，可設 1–1,000。超過限制會明確停止，不會悄悄抽樣。修改 `.env` 後重建容器設定。
- OpenAI API 使用文字與影像輸入；Codex CLI 使用影像附件；Claude CLI 使用 stream-JSON 影像區塊。CLI 模式沿用訂閱登入，不會改用 API 計費。
- 每頁記錄可讀程度、文字／圖片／表格／公式觀察與限制。長文件先分層壓縮證據，再綜合生成報告；完整逐頁文字與筆記可下載 Evidence JSON，頁面影像不存入歷史。
- 報告顯示已處理頁數、批次與逐頁閱讀資訊。「全部頁面已處理」不保證所有圖表、細字與公式都辨識正確；摘要壓縮也可能省略細節。
- 只有 PDF 下載或開啟失敗時才改用摘要。AI 批次失敗、頁碼缺漏或彙整引用錯誤會停止工作。失敗後重新產生會重新分析，不會自動續讀。
- 每個閱讀批次與彙整階段都使用 AI 額度，長文件需要更多時間。API 每次呼叫逾時 120 秒，CLI 使用 `CLI_TIMEOUT_SECONDS`；容器關閉最多等待 35 分鐘，重建可能中斷較長工作。
- 不含獨立 OCR 引擎、embedding／RAG、SCI 收錄驗證、Zotero 與 BibTeX 匯出。
- arXiv 包含預印本，產生的綜述內容仍需人工查核原文。
- 產生報告會將論文文字與頁面影像傳送給模型供應商，依設定使用 API 額度或自己的 CLI 訂閱方案；關閉瀏覽器不會取消後端工作。
