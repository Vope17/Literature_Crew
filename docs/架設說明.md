# Literature Crew 前後端架設說明

Literature Crew 是一個文獻搜尋與綜述工具：前端使用 **Vue 3 + Vite**，後端使用 **FastAPI + CrewAI**，Python 依賴以 **uv** 管理。本文件說明如何在本機架設開發環境與單一伺服器部署。

> 本應用程式沒有登入驗證機制，僅適合在本機（localhost）使用，請勿直接對外開放。

---

## 1. 環境需求

| 工具 | 版本 | 用途 |
|---|---|---|
| [uv](https://docs.astral.sh/uv/getting-started/installation/) | 最新版 | 安裝 Python 與後端依賴 |
| Python | 3.12 或 3.13（由 uv 自動安裝） | 執行後端 |
| [Node.js](https://nodejs.org/) | 22.12 以上 | 執行前端 |
| [pnpm](https://pnpm.io/installation) | 最新版 | 安裝前端依賴 |

確認安裝：

```sh
uv --version
node --version
pnpm --version
```

---

## 2. 專案結構

```
Literature_Crew/
├── backend/              # FastAPI + CrewAI 後端
│   ├── app.py            # API 路由入口
│   ├── literature.py     # PDF 擷取與 CrewAI 綜述流程
│   ├── paper_search.py   # arXiv 搜尋
│   ├── semantic_search.py# Semantic Scholar 備援搜尋
│   ├── review_jobs.py    # 背景綜述工作佇列
│   ├── storage.py        # SQLite 歷史紀錄與 PDF 儲存
│   ├── .env.example      # 環境變數範本
│   └── tests/            # 後端測試
├── frontend/             # Vue 3 + Vite 前端
│   └── src/              # App.vue、ReportView.vue、ReviewProgress.vue 等
└── docs/                 # 規格與說明文件
```

## 3. 後端架設

### 3.1 安裝依賴

```sh
cd backend
uv sync
```

`uv sync` 會依照 `uv.lock` 建立 `backend/.venv` 並安裝所有套件（第一次執行需要幾分鐘）。

### 3.2 設定環境變數

從範本建立 `.env`（已存在時不會覆蓋）：

```sh
cp -n .env.example .env
```

編輯 `backend/.env`：

```dotenv
OPENAI_API_KEY=你的-API-key
MODEL=openai/gpt-4o-mini

# SQLite 歷史紀錄與 PDF 儲存位置；相對路徑以 backend/ 為基準
HISTORY_DB_PATH=data/history.sqlite3

# 選填：Semantic Scholar 專屬 API key，可降低被限流的機率
SEMANTIC_SCHOLAR_API_KEY=

CREWAI_TRACING_ENABLED=false
OTEL_SDK_DISABLED=true
```

說明：

- **搜尋論文不需要 API key**；只有「Generate review」產生綜述時才需要 `OPENAI_API_KEY` 與 `MODEL`。
- API key 只存在後端，不會傳到前端，也不會寫入歷史紀錄。
- `.env` 已列在 `.gitignore`，不會被提交到 Git。
- 修改 `.env` 後必須**重新啟動後端**才會生效；系統環境變數的優先權高於 `.env`。

### 3.3 啟動後端

在**專案根目錄**執行：

```sh
uv run --directory backend uvicorn app:app --reload
```

或已經在 `backend/` 目錄中時：

```sh
uv run uvicorn app:app --reload
```

`--reload` 會在程式碼變更時自動重啟，適合開發使用。啟動後可檢查：

- API 文件：<http://localhost:8000/docs>
- 設定狀態：<http://localhost:8000/api/config>（`has_api_key` 為 `true` 代表 key 已讀取）

注意事項：

- **只執行一個後端程序**，不要加 `--workers`；綜述工作佇列存在單一程序中，一次執行一個綜述，其餘排隊。
- SQLite 資料庫會在第一次啟動時自動建立於 `backend/data/history.sqlite3`，請定期備份此目錄以保留歷史與 PDF。
- 後端中斷時正在執行的綜述，會在下次啟動時標記為失敗，可從歷史紀錄重新產生。

## 4. 前端架設（開發模式）

另開一個終端機，在專案根目錄執行：

```sh
cd frontend
pnpm install
pnpm dev
```

開啟 <http://localhost:5173>。Vite 會將 `/api` 請求代理到後端的 `http://127.0.0.1:8000`，因此**後端必須同時在執行**。

---

## 5. 單一伺服器模式

不需要 Vite 開發伺服器時，可先建置前端，再由 FastAPI 一併提供網頁：

```sh
pnpm --dir frontend install
pnpm --dir frontend build
uv run --directory backend uvicorn app:app
```

開啟 <http://localhost:8000>。

- FastAPI 只在**啟動時**偵測 `frontend/dist` 是否存在；建置後需重新啟動後端。
- 前端有修改時，需重新執行 `pnpm --dir frontend build`。

---

## 6. 執行測試

```sh
uv run --directory backend pytest
pnpm --dir frontend test
pnpm --dir frontend build
```

測試使用本機 PDF 與模擬服務，不需要 API key，也不會消耗額度。

## 7. 常見問題

**`error: No such file or directory (os error 2)`**
通常是 `uv run --directory backend` 在 `backend/` 內執行，導致尋找不存在的 `backend/backend`。請改在專案根目錄執行，或在 `backend/` 內去掉 `--directory backend`。

**`Port 8000 / 5173 is already in use`**
已有後端或前端在執行。可沿用現有程序，或先停止它：

```sh
lsof -i :8000
```

**前端顯示「Cannot reach the server」**
後端沒有啟動，或不在 8000 埠。請先啟動後端再重新整理頁面。

**模型標籤顯示「setup needed」、無法產生綜述**
`backend/.env` 缺少 `OPENAI_API_KEY` 或 `MODEL`。補上後重新啟動後端。

**搜尋顯示限流倒數**
arXiv 或 Semantic Scholar 暫時限制請求。等待畫面上的倒數結束再試；相同搜尋 15 分鐘內會使用快取。可設定 `SEMANTIC_SCHOLAR_API_KEY` 降低限流機率。

**`pnpm` 或 `node` 出現 `_nvm_load` / `maximum nested function level reached`**
這是 shell 中 nvm 延遲載入設定的問題，在非互動式 shell（例如 IDE 或腳本）中發生。可改用 Node 的絕對路徑執行，或在互動式終端機中操作。

## 8. 使用限制

- PDF 下載上限 20 MB，每篇擷取前 30,000 字元；下載失敗或掃描檔會改用摘要，報告中會標示資料覆蓋程度。
- 不含 OCR、SCI 收錄驗證、Zotero 與 BibTeX 匯出。
- arXiv 包含預印本，產生的綜述內容仍需人工查核原文。
- 產生綜述會將論文內容傳送給模型供應商並消耗 API 額度；關閉瀏覽器不會取消已在後端執行的工作。
